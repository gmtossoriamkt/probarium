# Настоящий HTTP 404 на хостинге (Timeweb App Platform, Caddy)

## Проблема
Сервер отвечает **200 OK и главной страницей** на любой несуществующий адрес
(`/xxx`, `/blog/нет-такой-статьи` и т. п.) — «мягкий 404». Яндекс.Вебмастер и поисковики
считают такие адреса живыми страницами-дублями главной. Причина — не в коде сайта, а в настройке
хостинга: включён режим «SPA / fallback на index.html». В репозитории файл `404.html` есть
(страница в общем стиле: шапка, футер, кнопка «На главную»), но сервер его не использует.

Проверить: `bash scripts/check-404.sh` — ожидается `404` для всех адресов.

## Что сделать в панели Timeweb (приложение Probarium)
1. **Настройки → Настройки деплоя → Редактировать**: отключить режим SPA / «перенаправлять все запросы
   на index.html» (название может отличаться), если такая опция есть. Сохранить и перезапустить деплой.
2. Если опции нет — **Настройки → Настройки веб-сервера → Настроить** и добавить правила Caddy:

```caddy
:80 {
    root * /srv
    encode gzip
    try_files {path} {path}/index.html
    file_server
    handle_errors {
        rewrite * /404.html
        file_server
    }
}
```

(`root` и порт подставьте как в текущей конфигурации панели — важны две вещи: `try_files {path} {path}/index.html`
БЕЗ завершающего `/index.html`-fallback на главную и блок `handle_errors` с `rewrite * /404.html`.)
3. Если панель не даёт менять веб-сервер — написать в поддержку Timeweb:
   «Нужен ответ 404 (с отдачей /404.html) для несуществующих путей статического приложения, сейчас отдаётся 200 с index.html (SPA-режим)».

## Проверка после изменения
```bash
bash scripts/check-404.sh
```
Статусы существующих страниц (`/`, `/blog/`, `/kontakty`) должны остаться 200.
